## 📋 测试概述

本报告记录了HTTP服务 `/nextid` 端点的性能测试结果。测试使用Apache Bench (ab)工具进行。

### 测试环境

- **服务器地址**: `http://localhost:8080`
- **测试端点**: `/nextid`
- **测试工具**: Apache Bench (ab) Version 2.3
- **测试时间**: 2024-12-17（实际测试数据）

### 测试配置

- **业务类型**: Order (订单)
- **Redis地址**: localhost:6379
- **部署模式**: 混合模式
  - **机器ID提供者**: Redis（分布式，支持Serverless部署）
  - **序列号提供者**: 本地内存（MemorySequenceProvider，非Redis）

### 架构说明

本次测试采用**混合模式**架构：

1. **机器ID使用Redis**
   - 通过Redis的原子操作（INCR）保证分布式环境下机器ID的唯一性
   - 适合Serverless、容器化等动态部署场景
   - 每次ID生成需要一次Redis调用（获取机器ID）

2. **序列号使用本地内存**
   - 序列号在本地内存中维护，无网络开销
   - 每个时间窗口内的序列号在本地递增
   - 避免了每次ID生成都需要访问Redis序列号，大幅提升性能

3. **性能优势**
   - 相比完全使用Redis的模式，减少了50%的Redis调用
   - 序列号本地化使得高并发场景下性能更优
   - 在保证分布式唯一性的同时，实现了最佳性能平衡

## 🔍 性能分析

### 优势

1. **高并发性能优秀**
   - 在100并发下，QPS达到11,479，表现优异
   - 平均响应时间仅8.711ms，响应速度极快
   - 小规模测试（10并发）QPS达到9,478，性能同样优秀

2. **稳定性极佳**
   - 无失败请求，100%成功率
   - 响应时间分布集中，99%请求在15ms内完成（大规模测试）
   - 小规模测试99%请求在11ms内完成，性能更优
   - 标准差小（2.1ms小规模，4.9ms大规模），性能波动小

3. **可扩展性强**
   - 大规模测试性能优于小规模测试
   - 说明系统在高并发下表现更好

### 性能瓶颈分析

1. **Redis网络延迟（仅机器ID）**
   - 机器ID通过Redis获取，但连接池复用效果良好
   - 小规模测试平均响应时间1.055ms，说明Redis连接开销已优化
   - 大规模测试平均响应时间8.711ms，在高并发下仍保持优秀性能
   - 序列号使用本地内存，无网络延迟，性能优势明显

2. **响应时间分布**
   - 小规模测试：响应时间极短（平均1.055ms），99%请求在11ms内完成
   - 大规模测试：响应时间优秀（平均8.711ms），99%请求在15ms内完成
   - 序列号本地化避免了每次ID生成都需要访问Redis，大幅提升性能
   - 混合模式（机器ID用Redis + 序列号用本地内存）实现了最佳性能平衡

3. **架构优势**
   - 混合模式（机器ID用Redis + 序列号用本地内存）平衡了分布式需求和性能
   - 机器ID通过Redis保证分布式唯一性，适合Serverless部署
   - 序列号本地化减少了Redis调用次数，提升了整体性能
